# Security policy

## Reporting a vulnerability

**Do not open a public issue for a security problem.**

Report it privately through GitHub's
[private vulnerability reporting](https://github.com/maumcrez-svg/flyfam/security/advisories/new)
on this repository. If that is unavailable to you, reach the maintainers on
[Telegram](https://t.me/flyfamrh) and ask for a private channel before sending any detail.

Please include what you found, how to reproduce it, and what you think the impact is. We
will acknowledge the report, tell you whether we consider it in scope, and keep you updated
until it is resolved or closed with a reason. Please give us a reasonable window to fix
anything real before disclosing it publicly.

## Before you look: nothing here signs a transaction

This is worth stating plainly, because it removes the entire class of vulnerability people
usually look for first.

- **No private key, mnemonic, keystore or credential is in this repository**, and none is
  read by any code path in it. `.env` files are gitignored.
- **The chain client is read-only.** It talks to an RPC endpoint through a six-method
  allowlist and has no method that writes, signs or broadcasts.
- **Trading is paper.** Positions are simulated against the real bonding curve. No order
  reaches a market and no real money is at risk.
- **Holder votes are off-chain**, verified by EIP-712 signature against a snapshot taken
  when the bag opened. A vote moves no funds.

## In scope

- Anything that would let an unauthorised party cast, change, suppress or replay a bag-room
  vote, or alter an eligibility snapshot after it was taken.
- Signature-verification flaws in the holder-access path: replay across bags, rounds,
  origins or chains; nonce or expiry handling; domain separation.
- Anything that lets untrusted input reach the filesystem, escape the loopback servers'
  path allowlists, or be served by the observer or spectacle servers beyond their
  documented roots.
- Integrity of the append-only audit journal and the hash-linked round records.
- A path through which any code here could sign or broadcast a transaction, read key
  material, or reach a write RPC method. If you find one, that is a serious bug by
  definition.
- Secrets, wallet addresses, holder identities or operational detail leaking into
  committed files, fixtures, test output or the public feed.

## Out of scope

- The loopback development servers (`observer/serve.py`, `spectacle/serve.py`) being
  unauthenticated. They bind `127.0.0.1` by design and are not meant to be exposed. Putting
  one on a public interface is a deployment mistake, not a vulnerability here.
- Denial of service through resource exhaustion against a local development server.
- Vulnerabilities in `upstream/`, which is a vendored, unmodified, byte-pinned copy of
  [fruitflydev/flycoinrh](https://github.com/fruitflydev/flycoinrh) kept for audit
  reproducibility. Report those upstream. We will note them in
  [`docs/UPSTREAM_NOTES.md`](docs/UPSTREAM_NOTES.md).
- Third-party dependencies and vendored browser libraries under `spectacle/static/vendor/`;
  report to their own projects, though we do want to hear if we are pinning a known-bad
  version.
- Smart contracts under `contracts/` that are not deployed. Say so in the report and we will
  treat it as a code-quality issue rather than a live vulnerability.
- The trading strategy losing money. That is not a vulnerability; see the disclaimer in the
  [README](README.md#disclaimer).
- Reports generated by an automated scanner with no demonstrated impact.

## Supported versions

This repository is a snapshot of a running system. Only the current `main` is supported;
there are no backports.
